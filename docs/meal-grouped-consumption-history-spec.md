# 먹은 기록 한 끼 그룹 UI 명세

## 목표

먹은 기록을 개별 consumption record 나열이 아니라 다음 3단 구조로 보여준다.

1. 날짜
2. 한 끼(분 단위 시간)
3. 같은 큐브 합산

예시:

- 오늘 · 총 9개
  - 10:26 · 총 5개
    - 청경채 1개
    - 소고기 1개
    - 귀리죽 1개
    - 쌀죽 2개
  - 17:40 · 총 4개
    - 쌀죽 2개
    - 브로콜리 1개
    - 소고기 1개

DB의 consumption record는 기존처럼 1개 섭취당 1행으로 유지한다. 화면에서만 그룹화한다.

## 범위

이번 구현에서는 새 DB 컬럼이나 migration을 추가하지 않는다.

기존 기능 중 다음은 그대로 보존한다.

- 재고 차감/복원
- NEW 재료 판정
- 반응 및 메모
- 식단 연결
- 개별 기록 수정/삭제
- 최근 7일 통계
- 가구별 RLS
- Realtime 동기화

## 그룹 규칙

### 한 끼 그룹

한 끼 키는 다음으로 만든다.

- 서울 기준 날짜
- 서울 기준 분 단위 시간(YYYY-MM-DD HH:mm)

같은 분으로 기록된 consumption record만 같은 한 끼로 묶는다.

10:26과 10:27은 자동으로 합치지 않는다. 시간 간격을 추정해 합치는 휴리스틱은 사용하지 않는다.

이유:
- 간식과 다음 식사를 잘못 합칠 수 있음
- 기존 데이터의 의미를 추정해서 변경하지 않음
- 사용자가 시간 수정으로 의도적으로 같은 시간으로 맞출 수 있음

### 같은 큐브 합산

같은 한 끼 안에서는 다음 값이 모두 같은 기록을 한 줄로 합산한다.

- 정규화한 cube_name
- unit_amount
- unit

표시는 `1개`, `2개`, `3개`처럼 underlying record 수를 합산한다.

실제 record id들은 그룹 내부에 모두 유지한다.

서로 다른 중량/단위의 기록은 이름이 같아도 합치지 않는다.

## 화면 구조

### 날짜 카드

기존 날짜 카드의 총 수량은 underlying consumption record 개수를 그대로 사용한다.

예:
- 오늘 9개

날짜 카드 상단의 기존 `선택 시간 수정` 버튼은 제거한다.

### 한 끼 블록

각 시간 그룹마다 다음을 표시한다.

- 시간
- 해당 한 끼 총 개수
- `시간 수정` 버튼

예:
- `10:26 · 5개    시간 수정`

시간 수정 버튼은 해당 한 끼의 record id만 수정 대상으로 연다. 다른 시간대 기록은 포함하지 않는다.

### 큐브 행

한 끼 안에서 같은 큐브는 한 줄로 합산한다.

예:
- `쌀죽    2개`

1개당 중량이 있으면:
- `쌀죽`
- `1개 30g · 총 2개`

수량은 화면 합산일 뿐 DB quantity나 consumption record를 병합하지 않는다.

## 반응 표시

반응은 원본 consumption record에 계속 저장한다.

### 같은 큐브 그룹의 모든 기록이 같은 반응/메모

한 번만 표시한다.

예:
- 😋 잘 먹음

### 같은 큐브 그룹 안에 반응 또는 메모가 서로 다름

임의로 하나를 대표값으로 선택하지 않는다.

- `반응 다름` 표시
- 상세 화면에서 각 기록별 값을 확인할 수 있게 한다.

### 한 끼 전체의 반응

모든 record의 반응과 메모가 완전히 동일한 경우에만 한 끼 공통 반응으로 한 번 표시하는 최적화를 허용한다.

조금이라도 다르면 record/큐브 그룹 기준 정보를 유지한다.

## 수정/삭제 UX

### 한 끼 시간 수정

한 끼 블록의 `시간 수정`을 누르면 현재 시간 그룹의 record만 연다.

기본 동작:
- 현재 한 끼 기록 전체를 대상으로 함
- 필요하면 일부 record 또는 같은 큐브 그룹을 선택 해제 가능
- 새 시간을 지정해 기존 atomic bulk RPC로 수정

따라서 오전 10:26 기록을 열었을 때 오후 17:40 기록은 애초에 수정 대상에 포함되지 않는다.

### 같은 큐브 1개

기존처럼 `수정·삭제`에서 바로 개별 record 편집 화면을 연다.

### 같은 큐브 2개 이상

메인 목록에서는 한 줄로 유지하고 `상세·수정`을 제공한다.

상세에서는:
- underlying record 목록
- 개별 수정
- 개별 삭제

를 제공한다.

초기 구현에서 여러 record를 한 번에 삭제하는 기능은 추가하지 않는다. 재고 복원과 식단 연결을 각각 정확히 처리하기 위해 삭제는 기존 개별 안전 경로를 유지한다.

## 선택 시간 수정 화면

현재 날짜 전체를 보여주던 선택 화면은 한 끼 범위로 축소한다.

같은 큐브가 여러 개인 경우 선택 목록에서도 중복 행을 그대로 반복하지 않는다.

예:
- 쌀죽 2개
- 소고기 1개

그룹 전체 선택/해제를 지원하고, 필요하면 상세에서 개별 record 선택을 조정할 수 있다.

## 기존 데이터

별도 backfill은 하지 않는다.

기존 consumption_records를 읽을 때 동일한 그룹 규칙을 적용한다.

따라서 과거 기록도:
- 같은 날짜
- 같은 분 단위 시간
- 같은 큐브 이름/중량/단위

이면 자동으로 합산되어 보인다.

## 구현 구조

화면 그룹 계산은 별도 순수 함수 모듈로 분리한다.

예:
- `src/lib/consumptionHistoryGroups.ts`

주요 모델:
- DayGroup
- MealTimeGroup
- CubeConsumptionGroup

UI component는 계산된 view model만 렌더링하도록 한다.

이렇게 하면 그룹 규칙을 UI JSX와 분리해 테스트하기 쉽고, 달력/통계 로직에 영향을 주지 않는다.

## 테스트 필수 항목

1. 같은 시간 + 같은 큐브 2건 → 한 줄 `2개`
2. 같은 시간 + 같은 이름 + 다른 중량 → 서로 다른 줄
3. 같은 큐브라도 10:26 / 17:40 → 서로 다른 한 끼
4. 10:26 / 10:27 → 자동 병합하지 않음
5. 한 끼 총 개수는 underlying record 수와 동일
6. 동일 반응 → 한 번만 표시
7. 서로 다른 반응 → `반응 다름`
8. 한 끼 시간 수정에 다른 시간대 record id가 포함되지 않음
9. 합산 행 상세에서 개별 수정/삭제 가능
10. 개별 삭제 후 합산 수량이 즉시 2개 → 1개로 변경
11. Realtime 변경 후 그룹 수량 재계산
12. 기존 NEW/달력/재고/식단 회귀 테스트 통과

## 이번 구현에서 하지 않는 것

- `meal_session_id` 컬럼 추가
- 시간 간격 기반 자동 끼니 추정
- 여러 consumption record를 DB 한 행으로 병합
- 여러 기록 동시 삭제
- 반응 값을 임의로 합쳐 하나의 대표 반응으로 저장

## 향후 확장 기준

실사용 중 한 끼 기록이 자주 10:26 / 10:27처럼 여러 분에 걸쳐 생성되어 사용자가 반복적으로 시간을 맞춰야 한다면, 그때 명시적인 `meal_session_id` 도입을 검토한다.

현재 단계에서는 DB 변경 없이 view grouping으로 해결하는 것이 가장 작은 위험으로 가장 큰 UX 개선을 제공한다.
