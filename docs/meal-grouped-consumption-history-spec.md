# 먹은 기록 동일 시각·동일 큐브 합산 표시 명세

## 목표

먹은 기록의 실제 데이터 구조는 그대로 유지하면서, 화면에서만 완전히 동일한 기록 행의 중복을 줄인다.

예:

- 10:26 쌀죽 1개
- 10:26 쌀죽 1개
- 10:26 소고기 1개

표시:

- 10:26 쌀죽 2개
- 10:26 소고기 1개

## 이번 범위

새로운 "한 끼" 개념은 만들지 않는다.

다음은 하지 않는다.

- meal_session_id 추가
- 1~2분 차이 기록 자동 합치기
- 시간 간격으로 같은 식사 추정
- consumption record DB 행 병합
- 기존 기록 backfill

따라서 10:26과 10:27은 같은 큐브라도 서로 다른 줄로 표시한다.

## 합산 기준

다음 값이 모두 같을 때만 화면에서 한 줄로 합산한다.

- 서울 기준 날짜
- 표시 시간 HH:mm
- 큐브 이름
- 1개당 중량
- 단위

같은 이름이라도 중량 또는 단위가 다르면 별도 줄로 유지한다.

## 데이터 보존

각 consumption record는 기존처럼 1개 섭취당 1행으로 유지한다.

따라서 아래 기능에는 영향을 주지 않는다.

- 재고 차감/복원
- NEW 판정
- 달력
- 식단 연결
- 반응/메모
- 개별 삭제
- Realtime
- 가구별 RLS

## 수정·삭제

합산 수량이 1개인 행은 기존과 동일하게 바로 수정·삭제한다.

2개 이상으로 합산된 행은 메인 목록에서 한 줄만 표시하고, `N개 상세·수정`을 열어 underlying record 각각을 개별 수정·삭제한다.

개별 기록 1건을 삭제하면 화면 합산 수량은 즉시 다시 계산된다.

예:
- 3개 → 1건 삭제 → 2개
- 2개 → 1건 삭제 → 1개

## 반응

합산된 underlying record의 반응과 메모가 모두 같으면 한 번만 표시한다.

서로 다르면 대표값을 임의로 선택하지 않고 `반응·메모 다름`으로 표시한다.

상세에서 각 record의 실제 반응과 메모를 확인하고 개별 수정할 수 있다.

## 시간 수정

기존 `선택 시간 수정` 기능은 그대로 유지한다.

이번 변경은 먹은 기록 목록의 중복 표시만 줄이며, 시간 수정의 선택 범위나 DB RPC는 변경하지 않는다.

사용자가 서로 다른 분으로 찍힌 기록을 같은 시간으로 맞추면, 저장 후 자동으로 같은 행으로 합산되어 보인다.

## 테스트 기준

1. 같은 날짜 + 같은 HH:mm + 같은 큐브 + 같은 중량/단위 2건 → 한 줄 `2개`
2. 같은 조건 3건 → 한 줄 `3개`
3. 같은 큐브라도 10:26 / 10:27 → 서로 다른 줄
4. 같은 시간·이름이어도 중량이 다름 → 서로 다른 줄
5. 같은 시간·이름이어도 단위가 다름 → 서로 다른 줄
6. 합산 행 상세에서 underlying record 각각 수정 가능
7. 동일 반응/메모 → 한 번만 표시
8. 서로 다른 반응/메모 → `반응·메모 다름`
9. 개별 삭제 후 합산 수량 재계산
10. 기존 재고/NEW/달력/식단/시간 수정 회귀 테스트 통과

## 향후 검토

실사용에서 1~2분 차이 기록을 같은 한 끼로 묶어야 하는 요구가 반복되면, 그때 별도의 명시적 식사 세션 모델을 검토한다.

현재 단계에서는 추정 로직을 추가하지 않고 동일 시각·동일 큐브 중복 행만 합산하는 것이 가장 안전한 범위다.
