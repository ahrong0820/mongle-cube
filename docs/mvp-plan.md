# 이유식 큐브 관리 사이트 — 간단 MVP 계획

> 현재 구현 기준안  
> 대상: 가족이 사용하는 휴대폰·태블릿 4~5대  
> 원칙: 냉동실 앞에서 바로 기록할 수 있는 작은 재고 페이지

## 한 문장 목표

큐브를 만들면 이름·제작일·개수를 등록하고, 간단한 주간 식단을 짠 뒤 먹었을 때 한 번 누르면 재고와 누적 기록이 연결된 모든 기기에 같이 보이게 한다.

## 첫 버전에 넣을 것

### 한 화면 재고 목록

- 권장섭취기한이 가까운 순서로 카드 표시
- 카드 내용: 큐브 이름, 제작일, 남은 개수, 1개 용량(선택), 14일 기한
- 상태는 `여유 / 3일 이내 / 기한 지남` 세 가지만 표시
- 카드에서 바로 `먹었어요 -1`, `+1`
- 수량은 0보다 작아지지 않음

### 먹은 기록

- `먹었어요`를 누른 날짜·시간과 큐브 이름을 자동 저장
- 날짜별로 최신 기록부터 표시
- 과거에 큐브 이름을 수정해도 당시 이름과 1개 용량은 그대로 보존
- 어느 날짜의 기록이든 날짜·시간, `잘 먹음 / 보통 / 거부 / 관찰 필요` 반응과 100자 메모 수정
- 선택한 기록을 개별 삭제하고 가능한 경우 재고 1개 복원
- 최근 7일 먹은 개수와 큐브별 반응 모아보기
- 월간 달력에서 날짜별 음식 이름·반응·D+를 보고 날짜를 눌러 상세 확인
- 달력 상세에서 베이스·토핑·간식, 첫 섭취 `NEW`, 큐브 기준 먹은 양, 이유식 일차 요약
- 공유되는 아기 생일·이유식 시작일 설정

### 7일 식단

- 월요일부터 일요일까지 날짜 선택
- 아침·점심·저녁·간식에 여러 큐브와 종류별 개수 추가
- 계획만 세울 때는 재고를 차감하지 않음
- 식단에서 `먹었어요`를 누른 큐브만 1개 차감하고 먹은 기록과 연결
- 계획보다 재고가 부족하면 경고하되 계획 자체는 저장 가능
- 완료 전 항목은 1개 단위로 식단에서 빼기

### 큐브 등록·수정

- 큐브 이름
- 제작 날짜와 시간
- 만든 개수
- 1개당 g 또는 mL(선택)
- 메모(선택)
- 기한은 제작 시각부터 냉동 14일로 자동 계산
- 수정과 삭제

### 가족 기기 공유

- 관리자가 만든 긴 초대 링크를 사용할 휴대폰·태블릿에서 한 번씩 열기
- 설정한 4~5개 브라우저가 연결되면 초대 링크는 자동으로 잠김
- 다른 가족은 별도 회원가입 없이 같은 냉동실에 연결
- 이후에는 같은 브라우저에서 바로 접속
- 브라우저 데이터를 지웠거나 휴대폰을 바꾸면 Supabase에서 교체용 링크를 새로 발급
- 한 기기에서 수량을 바꾸면 다른 모든 기기 화면도 갱신

## 화면 구성

화면은 아래쪽 네 탭만 사용한다.

1. `냉동실`: 남은 총수량, 기한순 큐브 카드, `먹었어요 / +1`, 수정
2. `달력`: 날짜별 음식·반응·NEW와 선택 날짜 상세 기록
3. `식단`: 7일 날짜와 네 끼 계획, 여러 큐브 추가, 먹은 완료 처리
4. `먹은 기록`: 누적 개수, 오늘·7일 요약, 날짜별 기록지, 기록 수정·삭제

등록·수정은 별도 페이지 대신 아래에서 올라오는 짧은 입력창으로 처리한다.

## 보관 기준

- 이 가정의 냉동 관리 기준은 제작 시각부터 14일
- 3일 이내면 임박 표시
- 14일이 지나면 기한 지남 표시
- 질병관리청의 국내 안내는 냉동 1주일이므로, 설정 화면 하단에 `가정 설정 14일 · 국내 공식 참고 7일`을 작게 명시
- 온도 이력이나 음식 상태가 의심되면 날짜와 관계없이 폐기

공식 참고: [질병관리청 영유아 식이영양](https://health.kdca.go.kr/healthinfo/biz/health/gnrlzHealthInfo/gnrlzHealthInfo/gnrlzHealthInfoView.do?cntnts_sn=5212)

## 기술 구성

```text
React + TypeScript + Vite
        ↓
Supabase의 큐브·먹은 기록과 실시간 갱신
        ↓
GitHub Pages 배포
```

- PWA와 오프라인 기능은 넣지 않음
- Google 로그인과 Google Cloud 설정은 사용하지 않음
- 관리자만 GitHub와 Supabase 계정 필요
- 나머지 기기는 별도 서비스 가입 없이 초대 링크만 사용
- 기본 `github.io` 주소를 사용하므로 도메인 구매 불필요

공유 링크 안쪽에서는 Supabase 익명 세션과 256비트 무작위 초대값을 사용한다. 초대값은 연결 직후 주소에서 지우며, 설정한 4~5개 기기가 연결되면 잠근다. 데이터는 연결된 기기만 읽고 수정하도록 제한한다. 이는 사용자 화면에 별도 로그인 절차를 만들지 않기 위한 최소한의 보호 장치다.

## 데이터

재고, 식단 항목, 먹은 기록을 각각 보관한다. 식단 항목 하나는 큐브 하나를 뜻한다. 한 번의 `먹었어요` 작업에서 세 데이터가 함께 저장되므로 서로 어긋나지 않는다.

| 필드 | 내용 |
|---|---|
| `id` | 제작분 ID |
| `household_id` | 여러 기기가 공유하는 냉동실 ID |
| `name` | 당근, 소고기, 브로콜리 등 |
| `prepared_at` | 제작 날짜·시간 |
| `expires_at` | 제작 시각 + 14일 |
| `quantity` | 현재 남은 개수 |
| `unit_amount` | 1개 용량, 선택 |
| `unit` | g 또는 mL, 선택 |
| `memo` | 선택 메모 |
| `updated_at` | 마지막 수정 시각 |

먹은 기록에는 당시 큐브 이름, 1개 용량, 먹은 시각, 식단 연결, 반응과 메모를 보관한다. 식단에는 날짜·끼니와 완료된 먹은 기록 연결만 둔다. 초대 연결을 위한 최소한의 가구·브라우저 연결 정보만 별도로 두며, 해동·원재료 관계 테이블은 만들지 않는다.

## 만들지 않을 것

- Google OAuth와 개인별 계정
- 알레르기 자동 판정·영양 분석·AI 식단 추천
- 해동·재가열 상태 관리
- 인쇄·라벨·QR
- 알림·이메일·푸시
- 월간 상세 통계와 성장 기준 비교
- 커뮤니티와 다른 사용자의 식단 탐색
- 여러 냉동실과 여러 가구
- 오프라인 편집과 PWA 설치
- 복잡한 백업·복원 화면
- 누가 수정했는지 남기는 감사 로그

실제 사용 중 꼭 필요하다고 느낀 기능만 나중에 하나씩 추가한다.

## 구현 순서

1. 로컬에서 한 화면 UI와 가짜 데이터 완성
2. 큐브 추가·수정·삭제와 `먹었어요 / +1`, 누적 기록 구현
3. 7일 식단과 아기 반응 기록 구현
4. Supabase 테이블과 최대 5개 브라우저 공유 연결
5. 휴대폰 여러 대에서 수량 동기화 확인
6. 로컬 결과 승인 후 GitHub에 업로드
7. GitHub Pages 주소를 사용할 가족 기기에 공유

## 완료 기준

- 큐브 등록이 10초 안에 끝남
- 자주 쓰는 큐브는 `먹었어요` 한 번으로 차감과 기록이 함께 처리됨
- 식단 완료와 되돌리기가 재고·먹은 기록과 항상 같이 반영됨
- 수량이 음수가 되지 않음
- 제작 시각 + 14일 계산이 정확함
- 연결된 휴대폰들의 수량이 5초 안에 같아짐
- 360px 폭 모바일 화면에서 불편 없이 사용 가능

여기까지 되면 첫 버전은 완성이다.
